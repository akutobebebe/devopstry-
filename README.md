# DevOps playground

Маленький HTTP-сервіс на Python без зовнішніх бібліотек. Код застосунку вже працює; інфраструктуру навколо нього будуватимеш ти. AWS поки не потрібен.

## Запуск локально

Потрібен Python 3.9+.

```bash
cd outputs/devops-playground
python3 app.py
```

В іншому терміналі:

```bash
curl http://localhost:8080/
curl http://localhost:8080/health
curl http://localhost:8080/info
```

Порт задається через `PORT`, назва середовища — через `APP_ENV`.

```bash
PORT=9000 APP_ENV=local python3 app.py
```

## Твої етапи

Не роби все разом. Після кожного етапу перевір, що сервіс відповідає на `/health`.

1. **Linux і процеси.** Запусти сервіс у терміналі, знайди його процес і порт. Зупини його. Спробуй змінити `PORT` і `APP_ENV`.
2. **Docker.** Допиши `Dockerfile` за підказками всередині. Збери образ, запусти контейнер з пробросом порту, передай `APP_ENV` через змінну середовища. Перевір `curl`.
3. **Compose.** Створи `compose.yaml`, щоб одна команда будувала й запускала сервіс. Додай healthcheck на `/health`.
4. **CI.** Створи GitHub Actions workflow, який на push запускає `python3 -m unittest discover -s tests -v`, а потім збирає Docker-образ. Нічого публікувати поки не треба.
5. **Terraform.** Коли перевіриш кредити AWS, спершу зробимо план без `apply`: провайдер, регіон, бюджет і мінімальний ресурс. Не коміть ключі доступу чи `*.tfstate`.
6. **Kubernetes.** Пізніше піднімемо локальний кластер (kind або minikube) і додамо Deployment + Service. AWS для цього не потрібен.

## Критерій готовності першого етапу

Ти можеш пояснити, що робить кожна команда запуску, і отримати JSON з `/health` та `/info`. Якщо щось ламається, покажи мені команду й повний текст помилки — розберемо разом.
